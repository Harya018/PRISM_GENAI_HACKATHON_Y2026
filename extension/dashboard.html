  1. The problem: a full-duplex voice agent hears continuously and can start acting before the user has finished a thought — disfluencies, pauses, and self-corrections are the norm, not the exception.
  2. Why pre-emptive calls fail: a realtime model can call a tool the instant it recognizes intent, before the user finishes correcting themselves — e.g. FDB-v3's own travel_19-style example, where a call fired on the first-mentioned destination is already wrong by the time the user finishes their sentence.
  3. The commit gate: every proposed call is buffered for a short debounce window before it executes for real, so a same-utterance correction can supersede it — the stale call is never recorded as having happened at all.
  4. The block-only resolver: cross-checks a buffered call's arguments against the turn's own transcript, and will only replace a value with one the user explicitly corrected away — it never injects a value the model didn't itself propose.
  5. Idempotency and confirmation: a repeated state-changing call with identical arguments is refused and returns the original result instead of running twice; a risky action additionally requires an explicit affirmative on record before it can execute at all.
See agent/commit_gate.py and agent/resolver.py for the actual implementation this diagram describes.
